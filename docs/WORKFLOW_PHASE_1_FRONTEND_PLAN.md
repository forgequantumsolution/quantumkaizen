## 1. Goal

Replace mock data in `client/src/features/workflows/` with live API integration, and add the React Flow workflow builder + lookup admin pages. After Phase 1 FE, users can:

1. Browse workflows (live data)
2. Open a workflow in a graph viewer
3. Design workflows in a React Flow canvas with full fork/join/decision support
4. Save → mutates the same workflow row in place (no versioning — see decision below)
5. Manage workflow lookups (types, stage statuses, action types, criteria, priorities)

**Out of scope for this phase:**
- Ticket UI (paired with backend Phase 2 — separate FE Phase 2 doc)
- Approval/SLA UI (paired with backend Phase 3)
- Audit log + signature modal (paired with Phase 4)
- Dashboards (Phase 5)

## 5. API client modules

### 5.1 `lib/api/workflow.ts` shape

```ts
import { api } from '@/lib/api';
import { useQuery, useMutation, useQueryClient } from '@tanstack/react-query';

// ── Types (will be replaced by openapi-typescript output once we wire it) ──

export interface WorkflowSummary {
  id: string;
  name: string;
  version: number;
  isLatestVersion: boolean;
  status: 'PENDING' | 'APPROVED' | 'REJECTED';
  workflowStatus: 'ACTIVE' | 'INACTIVE' | 'DRAFT' | 'DRAFT_UPDATE';
  type: { id: string; name: string } | null;
  stageCount: number;
  transitionCount: number;
  createdAt: string;
  updatedAt: string;
  createdBy: { id: string; name: string; email: string } | null;
}

export interface WorkflowDetail {
  workflow: { /* same as summary + parentWorkflowId, settings, etc. */ };
  flow_json: { nodes: BuilderNode[]; edges: BuilderEdge[] };
  meta: { warnings: string[] };
}

// ── Hooks ───────────────────────────────────────────────────────────────

export const workflowKeys = {
  all: ['workflows'] as const,
  list: (filters: ListWorkflowsQuery) => ['workflows', 'list', filters] as const,
  detail: (id: string) => ['workflows', 'detail', id] as const,
  draft: (id: string) => ['workflows', 'draft', id] as const,
};

export const useWorkflows = (filters: ListWorkflowsQuery) =>
  useQuery({
    queryKey: workflowKeys.list(filters),
    queryFn: () => api.get('/workflows', { params: filters }).then(r => r.data),
  });

export const useWorkflow = (id: string | undefined) =>
  useQuery({
    queryKey: workflowKeys.detail(id!),
    queryFn: () => api.get(`/workflows/${id}`).then(r => r.data),
    enabled: !!id,
  });

export const useCreateWorkflow = () => {
  const qc = useQueryClient();
  return useMutation({
    mutationFn: (input: { name: string; typeId?: string }) =>
      api.post('/workflows', input).then(r => r.data),
    onSuccess: () => qc.invalidateQueries({ queryKey: workflowKeys.all }),
  });
};

export const useSaveWorkflow = (id: string) => {
  const qc = useQueryClient();
  return useMutation({
    mutationFn: (body: SaveWorkflowBody) =>
      api.put(`/workflows/${id}`, body).then(r => r.data),
    onSuccess: () => {
      qc.invalidateQueries({ queryKey: workflowKeys.detail(id) });
    },
  });
};

export const useSaveLayout = (id: string) => useMutation({
  mutationFn: (positions: Array<{ canonicalId: string; position: { x: number; y: number } }>) =>
    api.post(`/workflows/${id}/save-layout`, { positions }).then(r => r.data),
});

export const useSoftDeleteWorkflow = () => { /* DELETE */ };
export const useWorkflowDraft = (id: string) => { /* GET + POST drafts */ };
```

## 6. Builder canvas details

### 6.1 React Flow integration

```ts
// builder/WorkflowBuilderPage.tsx
import { ReactFlow, Background, Controls, MiniMap, useNodesState, useEdgesState, Connection } from 'reactflow';
import 'reactflow/dist/style.css';

const nodeTypes = {
  stage: StageNode, fork: ForkNode, join: JoinNode, decision: DecisionNode,
};

function WorkflowBuilderPage() {
  const { id } = useParams();
  const { data, isLoading } = useWorkflow(id);
  const [nodes, setNodes, onNodesChange] = useNodesState([]);
  const [edges, setEdges, onEdgesChange] = useEdgesState([]);
  const [selected, setSelected] = useState<string | null>(null);
  const [validationErrors, setValidationErrors] = useState<string[]>([]);

  // Initialise from server data
  useEffect(() => {
    if (data) {
      setNodes(deserializeNodes(data.flow_json.nodes));
      setEdges(deserializeEdges(data.flow_json.edges));
    }
  }, [data]);

  // Layout autosave (debounced)
  useDebouncedEffect(() => {
    saveLayoutMutation.mutate(extractPositions(nodes));
  }, [nodes], 1500);

  return (
    <div className="grid grid-cols-[200px_1fr_320px] h-screen">
      <NodePalette />
      <ReactFlow
        nodes={nodes} edges={edges}
        nodeTypes={nodeTypes}
        onNodesChange={onNodesChange}
        onEdgesChange={onEdgesChange}
        onConnect={onConnect}
        onNodeClick={(e, n) => setSelected(n.id)}
        fitView
      >
        <Background /><Controls /><MiniMap />
      </ReactFlow>
      <InspectorPanel
        nodeId={selected}
        nodes={nodes}
        onNodeUpdate={updateSingleNode}
      />
    </div>
  );
}
```

### 6.2 Node types — handle layout

| Node | Sources | Targets |
|---|---|---|
| Stage | 1 (default) | 1 |
| Fork | N (`branch-0`..`branch-N-1`) | 1 |
| Join | 1 | N (`branch-0`..`branch-N-1`) |
| Decision | N (XOR — frontend renders branch list with conditions) | 1 |

When user changes `branchCount` in Fork/Join inspector, the node component re-renders with the new handles. Existing edges with `sourceHandle`/`targetHandle` matching the new range stay; orphaned ones get visually flagged.

### 6.3 Inspector forms (RHF + Zod)

Each inspector is a small form bound by `react-hook-form` with a Zod schema. On change → updates the corresponding node's `data` field. No separate save — node data is part of the canvas state until top-level Save.

Example `StageInspector.tsx` schema:
```ts
const stageInspectorSchema = z.object({
  label: z.string().min(1),
  is_initial_stage: z.boolean(),
  email_notification: z.boolean(),
  primary_actions: z.array(z.object({
    stage_status_id: z.string().uuid(),
    type: z.literal('primary'),
    action_criteria_id: z.string().uuid().nullable().optional(),
    roles_id: z.array(z.string().uuid()),
    employees_id: z.array(z.string().uuid()),
  })),
  secondary_actions: z.array(/* same shape with type:'secondary' */),
});
```

### 6.4 Save flow

```
1. User clicks "Save" in toolbar
2. WorkflowBuilderPage.handleSave():
   a. body = serialize(nodes, edges, settings)
   b. saveMutation.mutate(body)
3. Mutation handler:
   - On success: toast.success(msg); invalidate detail query
   - On 400 with validation_errors: setValidationErrors(arr); show ValidationErrorPanel
   - On other errors: toast.error
4. ValidationErrorPanel renders a collapsible list. Clicking an error highlights the offending node (via setSelected + a ring class)
```

### 6.5 Layout-only autosave

`useDebouncedEffect` watches `nodes`. After 1.5s of no movement, fires `saveLayoutMutation.mutate(positions)`. No version bump, no validation. Failure surfaces a toast but doesn't block the user.

### 6.6 Discard / leave protection

If `nodes` or `edges` differ from the server snapshot, show a "discard changes" confirm modal before navigating away. Use `useBlocker` from React Router.

## 13. Risks

| Risk | Mitigation |
|---|---|
| Inspector form complexity (deep nested arrays for actions) | Use `useFieldArray` from RHF; keep each action as its own sub-form |
| React Flow handle re-render after branchCount change | Force-remount the node via `key={branchCount}` or use stable handle IDs |
| Layout autosave races with main save | Debounce + tag the layout request; cancel in-flight if main save fires |
| Existing `WorkflowsPage` uses mock data — sidebar/header may depend on it | Audit imports first; if anything outside `features/workflows/` imports `data.ts`, leave `data.ts` in place but stop new imports |
| Backend's `flow_json` shape includes structural keys we ignore (additional_data warnings, etc.) | Use Zod `.passthrough()` on parser; warnings shown in a non-blocking panel |
| OpenAPI types divergence between manual + generated | Manual types as a shim only; switch to generated once a single hook is converted as proof |
| antd vs custom UI kit hybrid | Stay consistent within a feature: lookups admin uses antd Tabs/Table; builder uses lucide+Tailwind for canvas-adjacent UI |
